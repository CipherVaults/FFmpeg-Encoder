# Regular v0.7 R06: bind the Files disclosure to its owning editor

November 21, 2026 Cairo. Source candidate on exact 133; no native, package or milestone acceptance.

**Issue and decision.** Checkpoint 133 could expose a Files button in Encode/Remux even when no list was prepared, or when Current Jobs physically held the single shared list. Its prior expanded label did not describe anything under the editor. Hide the trigger and clear its expanded state when that editor does not own the visible batch panel, including first paint. Do not turn it into a second Jobs control, auto-open Jobs, alter the remembered drawer choice, or duplicate the list. If the old trigger had focus when the list moved, focus returns to the existing workspace before hiding. A click or Escape on a no-longer-owning editor cannot mutate the drawer choice. When a list returns, restore the owner's control according to the retained open and effective preview state; do not steal focus. The existing Jobs tab, Cancel bar, queues, settings and permissions are untouched.
