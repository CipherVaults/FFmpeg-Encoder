## Revision after independent design review

This remains disabled source, not activation. `loadQualification()` checks the compact record and source closure, then unconditionally throws `LINUX_PRODUCT_INTEGRATION_PENDING` before the shell opens a runtime. Neither JSON flags nor exported inventory checks bypass that stop. Native proof and integration-review references remain null.

The compact reader now admits at most 16 KiB before allocation, rejects nonregular/multiply-linked files and symbolic roots/ancestors, opens with no-follow/nonblocking flags, reads through a retained descriptor with a one-byte growth guard, and rechecks descriptor/path identities and realpath. Its exact digest and closed reviewed schema/values must match; the result is recursively frozen. This is not a generic caller-supplied manifest. Same-user adversarial ancestor races are not claimed eliminated by pathname rechecks.

A fixed 115-file source closure preserves all 97 original measured calibration-producer digests unchanged and adds the actual product shell/service/main/preload/renderer literal import closure. The two producer-check positions previously removed from service construction now perform this real bounded hash verification before and after qualification loading. Per-file admission is at most 4 MiB, total 32 MiB and at most 256 files; retained-handle identity rules also apply. The loader containing these pins is the reviewed code trust anchor: self-authentication is impossible, and future packaging must bind its bytes through the reviewed package inventory. These checks establish current disk/source identity, not a defense against a compromised JavaScript process or proof of measured semantics for arbitrary revised code.

The source closure is intentionally conservative and includes calibration producer source, but no raw artifact reports or runtime bytes. A future smaller package closure must be reviewed explicitly rather than silently dropping producer pins. Unchanged raw-report hashes alone are not accepted as a substitute for live producer identity. The compact data exports return no runtime handle or encoding permission.

Twelve pure/file/injected controls pass. They cover the real pending stop, immutable bounded record, modified/oversized/linked/nonregular records, changed source refusal, positive injected one-family shell composition, construction failure cleanup, real option-class rejection, two service source checks, unsupported queue admission, cancellation/drain ordering, private-handle/dependency rejection and the frozen Windows construction block (allowing only the existing declaration-scope move). The positive paths replace internal module imports inside the test VM; no production dependency-injection option or activation switch is added. They do not launch FFmpeg, Electron, media, native dialogs or shell access. A first Windows baseline comparison test needed its normalization corrected for the already-reviewed combined variable declaration; no product change was made for that test correction.

Remaining activation obligations are unchanged: independently accepted native proof and integration decision, actual policy/source-closure review, packaging the exact modules and notices, pinned Linux Electron identity and dependency strategy, relocated real UI publication/output access/shutdown and independent audit. The existing Windows build still does not package this route. This revision does not authorize executable staging, public redistribution, portable distro support or a default change.
