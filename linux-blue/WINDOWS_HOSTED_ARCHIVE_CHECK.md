# Guarded hosted archive check: source-only implementation

This workflow admits the exact repository/development ref and first run attempt only. Its push trigger is limited to changes including this workflow path; ordinary source-only commits do not trigger acquisition. The checked-out head must match the push event after-SHA. Optional manual dispatch additionally requires exact40hex approved_sha. Operational approval must identify the exact revision and bounded archive-only attempt before dispatch; the input is a guard against mistaken revision, not a grant of permission. A rerun is refused; a new explicitly authorized execution is required. The first reviewed workflow-introduction push is the intended execution route; no default-branch change or duplicate dispatch is needed. Manual discovery still depends on default-branch registration. This implementation has not been pushed or dispatched.

The wrapper checks actual Git HEAD, Windows platform and a read-only Windows volume query for the RUNNER_TEMP drive. It measures that exact local volume against the unchanged27GiB+archive threshold, not an assumption from GitHub's14GB advertised standard-runner storage. It does not search arbitrary volumes, clean disk or lower a floor. A separately documented local runner volume could be evaluated in later reviewed source; this wrapper chooses only RUNNER_TEMP.

When sufficient space exists it calls the reviewed V3 archive-only acquisition once, rereads both archives against pins and emits ARCHIVES_VERIFIED_ONLY. Otherwise it returns BLOCKED_RESOURCE_FLOOR without candidate downloads; transport/integrity failure returns ACQUISITION_FAILED. Both unsuccessful states produce a nonzero step. No extraction, npm install, FFmpeg/Electron/media execution, CPU admission or packaging occurs. Checkout/setup-node can fetch trusted tooling, and Git/PowerShell volume probes execute trusted helpers even when candidate acquisition is blocked.

A fresh exclusively created report under an owned RUNNER_TEMP directory is bounded to32KiB, closed/read back, identity/schema/field-allowlist checked and hashed before emitting report_ready/path/digest step outputs. The upload action accepts only that signaled path, including a reportable nonzero outcome, never a fixed pre-existing repository file. Missing/unattested reports are not uploaded and mean incomplete evidence. The one explicit JSON report is retained3days; no archives, raw logs, media or private records are uploaded. Partial candidate files remain ephemeral on the runner; report retention does not back up payload bytes. Ordinary same-user filesystem check/dispatch race limitations remain.

Readback after an eventual authorized run must bind exact commit/run/attempt, both job conclusion and uploaded report contents/hash. Existing source-contract CI remains separate. Archive verification is never installation/eligibility proof. Guarded extraction, final binary/notice verification and service admission need separate reviewed work.

V2 readback uses retained-handle bounded JSON reads (32KiB+1 sentinel), deep content equality and exact byte/hash verification, with owned-directory rechecks before step output. The archive transfer receipt uses the same bounded JSON primitive and only its expected fixed filename.

V3 one-introduction restriction: both the workflow job and wrapper pin previous remote060 commit `97ca51ff99cce5e4b382b2a9d0445949cb416cc8`; force/create/delete pushes are rejected. This permits only the intended ordinary successor introduction, not later workflow-file edits. If the remote parent changes before publication, revise and independently review the parent guard before publishing. Optional manual exact-revision execution still needs separate bounded authorization; never dispatch a duplicate of the introduction run.
