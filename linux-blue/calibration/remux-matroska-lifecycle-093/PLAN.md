## Requested invocation ledger and finite resources
Four Prepare calls total: success, collision, generated rescan, cancellation. Each uses inspectMetadata once at most, not duration-dependent inspectInput windows; cache hits may reduce actual calls. Runtime currentness hashes pinned files and does not add version-probe children. Each of the two possible execution paths can require one copy child, one output metadata probe, and at most14 collector calls (2packet listings, up to4unique extradata fetches,2H264 parameter scans,2AAC admission windows,2bounded key-window invocations,2complete PCM passes). Thus total maximum4 + 2×(1+1+14) = 36 requested children. Success-owner maximum3+16=19; cancellation-owner maximum1+16=17. Existing adapter ceiling32 per owner need not expand. Outer driver should enforce36 globally; no inference that every requested call actually spawned.

The collector can use paired pipes; retain observed maximum two concurrent child identities from existing081, not a false serial-one promise. A refused pre-spawn request and a child exit are separate counters. Source-derived shared production evidence budgets remain unchanged; the private standalone media harness's16MiB override does not silently become lifecycle-service policy. Use existing512MiB owned-tree ceiling,27GiB free floor,120s child cap,600s total outer bound, with cancellation requested at540s and settled cleanup before final acceptance. Authoritative monotonic checks through hashing and final persistence must prevent an expired pass. No scope/limit auto-expansion.
