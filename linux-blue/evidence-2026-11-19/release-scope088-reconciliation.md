## Decision

The Linux candidate is a useful working integration, but it is not yet the accepted v0.7 feature set. Do not equate one native proof per fixed family with completion of Q/R/S. After the current AV1 native check, the next product change should broaden the **ordinary Full/Keep Source CPU composition through the existing shared service**, rather than add another fixed-fixture family. Begin by making ordinary H265 Full/source available independently of the measured trim/resize selector and supporting the existing validated CPU preset/quality controls. Reuse shared validation and fixed executable ownership. This directly repairs P04/R05 usability: currently H265 selection means only slow/25 measured families, not ordinary Full source encoding.

This is a proposed next implementation, not permission to delete qualification gates. First separate arbitrary laboratory caps from essential media/safety admission, inspect exact accepted profile/input predicates and runner budgets, and derive explicit operational limits. Preserve format/color/track compatibility checks, no-overwrite/source identity and cancellation. Do not simply remove assertions, enable all inherited profiles, or claim all input formats from a single result.

## What shared validation already provides

`src/encoder-service.cjs` owns inspection, preparation, sequential execution, current plan authority, cancellation, stage validation and publication. `src/inspection.cjs:429 validateOutput` validates the selected profile, mapped stream count/order, output codec, dimensions, depth/chroma/alpha, accepted SDR signaling, cadence/duration tolerance, plus subsequent stream/metadata checks. It is deliberately a compatibility validator, not a full decode proof or precision-boundary guarantee.

`src/encode-operation.cjs:210` separates Full/no-resize/no-precision compatibility from transformed paths. `src/operation-contract.cjs` already resolves geometry, range, audio policies, no-downmix/no-resample, container limitations and effective requests. Existing collector/qualification layers supply measured transformed acceptance. `src/remux-catalog.cjs` and remux contract/collector/validator own compressed essence/clock/representation verification. Reuse them with exact runtime adaptation; do not weaken into probe-only remux validation.

Therefore do not rerun every historical calibration or every codec×preset×resolution×container combination. Group changes by mechanism: command/compatibility profile, precision timing/audio collector, geometry transformation, remux container representation, and platform runtime/packaging. Test boundary negatives and one representative real endpoint per newly exercised mechanism, with an additional case only for a distinct branch (e.g. copied audio vs multitrack/ancillary). Existing source tests can cover settings permutations; actual artifact-bound acceptance must cover changed runtime/composition boundaries.

## Concrete next work order

1. Finish 088's already planned real AV1 service/app path, without general performance or quality equivalence claims.
2. Implement ordinary H265 Full/source in the unified composition through the same accepted compatibility path; make existing validated CPU preset/quality choices usable with explicit capability filtering. Keep AV1's initial bounded tuple until its settings range is reviewed. Add pure settings/boundary tests and actual EncoderService prepare/fresh-route/cancel controls; use one representative non-fixture-identity-bound H264/AAC Full→HEVC publication through the app, plus ordinary H264 regression only where changed shared dispatch warrants it. Review resource budgets rather than leaving an arbitrary ten-minute ceiling as an undocumented product feature.
3. Next Q priority: integrate precision trimming of an ordinary AAC capture through existing precision-audio policy, and broaden remux by existing container-policy branches (first the most useful MKV↔MP4 branch, preserving audio limitations). Do not make each new fixture a permanent product route. Maintain explicit uncovered VFR/multitrack/ancillary cases and their implementation reasons.
4. In parallel finish the Ubuntu signed toolchain/source/runtime manufacture decision; resolver's assertion failure before baseline fields is a task failure, not proof Ubuntu cannot work. Existing host-hash pins mean the present package cannot be advertised as Ubuntu-compatible.
5. Reconcile all remaining N–S rows against current source and final support table, then final-source integration/interaction QA, exact Linux and Windows deliverables and owner checklist. Ahmed's Windows/RTX test is last; v0.8 may start on a separate branch only after useful independent v0.7 work and candidate freeze, not instead of it.

No estimate or claim of complete v0.7 is warranted from the number of checkpoint records. The next user-visible gain should be broader practical input/settings support and actual release manufacture, not more preservation infrastructure.
