# Minimal next implementation: verified base inventory and isolated simulation

Proposal only. Frozen100 untouched. No acquisition, APT, rootfs extraction or execution performed. This is the next concrete adapter, not a new manufacture system or complete dependency-lock claim.

## Three small owned pieces
1. `base_inventory.py`: accepts a previously signature-verified checksum manifest and one exact owned Ubuntu Base archive. No network. Verify selected archive Size/SHA256, no-follow ordinary file/current UID and stable descriptor/name identity. Stream gzip/tar without extraction; scan through complete EOF. Read exactly one canonical regular `var/lib/dpkg/status` (allow one leading `./`, reject duplicate normalized names or link substitution). Keep only that member; skip other payload bodies without following links. Reject sparse/unsupported extensions for the selected member. Parse with the existing strict paragraph parser and retain installed Package/Version/Architecture/Essential/Pre-Depends/Depends/Provides/Multi-Arch fields. Preserve exact status bytes as the solver seed. Missing member, malformed status, foreign architecture or ambiguous duplicate tuple stops. Additional control members are not initially necessary.
2. A small acquisition wrapper, separately released later: fetch exactly the official versioned amd64 archive plus SHA256SUMS and detached signature, no redirects or alternate mirrors, bounded bytes/deadline. Verify checksum signature using a separately pinned Ubuntu image-signing keyring/fingerprint, not an assumed equivalence with ubuntu-archive-keyring. Then bind the selected signed checksum line and actual archive size to inventory.py. A manifest digest passed by an untrusted caller is not authentication. Do not fabricate pins now; signing key and exact digest remain release prerequisites.
3. `seed_solver.py`: reuse resolver100's explicit owned APT_CONFIG construction and bounded child helper, replacing the live-runner status read with the exact verified seed. No inherited APT hooks/configuration. Permit only amd64/all and the same official noble/update/security sources; retain signature/Valid-Until checks, no recommends, no retries and no redirects. Main supplies genuine authenticated index records, not an auth boolean. Never call dpkg or install packages. Emit seed identity, selected roots, exact simulation transaction and signed-stanza associations; ready remains false.

## Fixed prospective commands/data
- Signature check shape: `/usr/bin/gpgv --keyring <reviewed-image-keyring> <SHA256SUMS.gpg> <SHA256SUMS>` inside the owned bounded wrapper. Keyring fingerprint/content must be frozen first.
- Metadata update: `/usr/bin/apt-get update --error-on=any`, with the existing explicit owned config and no host mutation.
- Simulation: `/usr/bin/apt-get -s --no-install-recommends install <the existing 23 ROOTS>`. Its status is the verified base, not empty and not the 1,212-package hosted inventory. Any proposed removal or base upgrade remains review-required, not automatic consent. No extra apt-cache loop over the entire hosted inventory.
- Read exact official signed Packages stanzas for tuples actually selected; retain seed nodes even if APT emits no Inst line. Record all Essential/base nodes and explicit shell/Python/compiler roots. Base .deb availability may differ from the current index snapshot; missing old tuples must remain unresolved, not silently relabeled as authenticated.

## Proposed stop bounds and inert controls
Archive compressed cap 64 MiB; decompressed traversal cap 512 MiB; 100,000 members; selected status cap 8 MiB; 2,000 base tuples. These are prospective refusal bounds, not measured image claims. Metadata keeps existing100 per-index/aggregate/decode limits; proposed combined adapter 15 minutes, at most 8 owned child invocations, 2 GiB observed owned tree, 27 GiB free floor and 8 MiB per log. Any envelope conflict must be resolved in review, never automatically raised. No raw system inventory or private logs uploaded.

Tests: valid synthetic tar; status missing/duplicate/linked/sparse; traversal and expanded-size limits; truncated gzip/tar; malformed duplicate status fields; changed archive identity; bad signature/digest adapter result; foreign arch; exact owned config and argv; refusal of host config/hooks; base change/removal refusal; unsigned/missing tuple. Use synthetic bytes and injected child adapters only.

## Honest stopping point
This produces an authenticated seed plus bounded official candidate transaction, not full provider/alternative dependency closure. APT's printed Inst/Conf transcript omits already-present dependencies and selected alternative reasons. Do not write a parallel dependency solver or label the transcript a lock. A later narrow libapt-backed selected-state exporter, with its own pinned interpreter/library payload and inert provider/version tests, is needed if existing APT interfaces cannot expose the selected reachable graph. Actual tool .deb payload verification, isolated provisioning, offline085 manufacture and ELF/runtime acceptance remain separate gates. Preserve CPU AV1 and all original085 sources/flags.
